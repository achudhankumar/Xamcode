How does BBR congestion control differ from TCP Cubic?
AURA Tutor Response

TCP Cubic throttles window size only after packet loss buffers overflow. BBR model-bases delivery rate: it continuously estimates bottleneck bandwidth and minimum round-trip time, preventing bufferbloat.

How this estimate works

Remaining effort = open roadmap tasks (seeded from docs/REMAINING-ROADMAP.md) + open bug repair effort by severity (critical 16h · high 8h · medium 4h · low 2h) + unresolved blockers — with blockers that overlap an open bug deduplicated, so the same work is never counted twice.

The projected date is remaining effort ÷ velocity expressed in calendar days. No date is hardcoded anywhere: the target comes from the server on every refresh, and only the seconds between refreshes are interpolated locally. Commits and CI runs never verify milestones and never move this number. It is a model projection, not a promise.
